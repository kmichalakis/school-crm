# Τεχνική τεκμηρίωση Σχολικού CRM

Τελευταία ενημέρωση: 2026-05-24

## 1. Σκοπός εφαρμογής

Το Σχολικό CRM είναι web εφαρμογή για διαχείριση απουσιών σχολικής μονάδας. Καλύπτει:

- σύνδεση χρηστών με ρόλους,
- απουσιολόγιο ανά τμήμα, ημερομηνία και ώρα,
- υπογραφή απουσιολογίου από εκπαιδευτικούς,
- διαχείριση σχολικών δεδομένων ανά σχολικό έτος,
- εισαγωγή δεδομένων από Excel,
- ημερολόγιο εργάσιμων/μη εργάσιμων ημερών,
- αναφορές, εκτυπώσεις, dashboard και ειδοποιήσεις γονέων.

Η εφαρμογή είναι σχεδιασμένη ώστε το tablet του τμήματος να λειτουργεί απλά, ενώ ο admin έχει πλήρη πρόσβαση στα δεδομένα και στις ρυθμίσεις.

## 2. Τεχνολογίες

- Next.js 15 με App Router
- React 19
- TypeScript
- PostgreSQL
- Prisma ORM
- Server Actions για admin/αναφορές/ειδοποιήσεις
- API Routes για login, logout, attendance και exports
- `xlsx` για import/export Excel
- PBKDF2 hashing για κωδικούς
- HMAC-signed cookie sessions

## 4. Τοπική εγκατάσταση

Απαιτείται Node.js 20+ και PostgreSQL.

```bash
npm install
npm run prisma:generate
npm run prisma:migrate
npm run dev
```

Για καθαρό admin χωρίς demo δεδομένα:

```bash
ADMIN_USERNAME=admin ADMIN_PASSWORD=admin npm run db:bootstrap-admin
```

Για demo δεδομένα:

```bash
npm run db:seed
```

## 5. Environment variables

```text
DATABASE_URL=postgresql://...
NEXTAUTH_SECRET=τυχαίο-μεγάλο-secret
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ισχυρός-αρχικός-κωδικός
EMAIL_FROM=attendance@example.edu
RESEND_API_KEY=προαιρετικό-api-key-για-πραγματική-αποστολή-email
```

Σημαντικά:

- Το `DATABASE_URL` χρησιμοποιείται από Prisma.
- Το `NEXTAUTH_SECRET` υπογράφει τα session cookies. Σε production πρέπει να είναι σταθερό και μυστικό.
- Το `ADMIN_USERNAME` και `ADMIN_PASSWORD` χρησιμοποιούνται από `prisma/bootstrap-admin.ts`.
- Το `RESEND_API_KEY`, αν οριστεί, επιτρέπει πραγματική αποστολή email από το μενού `Έλεγχος`. Αν λείπει, οι ενημερώσεις μένουν στην ουρά.

## 7. Ρόλοι χρηστών

Οι ρόλοι ορίζονται στο Prisma enum `UserRole`.

| Ρόλος | Περιγραφή |
| --- | --- |
| `CLASS_TABLET` | Χρήστης τμήματος/απουσιολόγος. Μπαίνει στο απλό περιβάλλον τμήματος. |
| `TEACHER` | Εκπαιδευτικός. Βλέπει μαθήματα και τμήματα ευθύνης, υπογράφει τα δικά του μαθήματα. |
| `ADMIN` | Διαχειριστής. Έχει πλήρη πρόσβαση και μπορεί να λειτουργήσει και ως εκπαιδευτικός. |
| `PARENT` | Γονέας. Βλέπει απουσίες μαθητή, εκτυπώσιμη αναφορά και πρόγραμμα τμήματος. |

Το manual χρήστη καλύπτει απουσιολόγο, εκπαιδευτικό, admin και γονέα.

## 8. Authentication και ασφάλεια

### Login

Endpoint: `POST /api/login`

Ροή:

1. Κανονικοποιεί το username σε lowercase.
2. Αναζητά `User`.
3. Ελέγχει προσωρινό κλείδωμα.
4. Ελέγχει κωδικό με PBKDF2.
5. Σε αποτυχία αυξάνει `failedLoginCount`.
6. Στις 5 αποτυχίες θέτει `lockedUntil` για 15 λεπτά.
7. Σε επιτυχία μηδενίζει αποτυχίες και γράφει `lastLoginAt`.
8. Δημιουργεί HMAC-signed session token.

### Session

Το cookie ονομάζεται `school_crm_session`.

Ιδιότητες:

- `httpOnly`
- `sameSite: lax`
- `secure` σε production
- διάρκεια 10 ώρες

Το token περιέχει:

- `userId`
- `username`
- `role`
- `classId`
- `mustChangePassword`
- `expiresAt`

### Password policy

Ο ελάχιστος κωδικός είναι 4 χαρακτήρες. Επιτρέπονται αριθμητικά PIN. Ο κωδικός δεν πρέπει να περιέχει το username.

## 9. Βασικά μοντέλα δεδομένων

### `SchoolYear`

Κρατά σχολικό έτος, ημερομηνία έναρξης/λήξης και status.

Πεδία-κλειδιά:

- `name`, π.χ. `2025-2026`
- `startsOn`
- `endsOn`
- `status`: `ACTIVE` ή `ARCHIVED`

### `SchoolCalendarDay`

Κρατά εξαιρέσεις ημερολογίου ανά σχολικό έτος.

Προεπιλογή συστήματος:

- Δευτέρα έως Παρασκευή είναι εργάσιμες.
- Σάββατο και Κυριακή δεν είναι εργάσιμες.

Ο πίνακας αποθηκεύει μόνο εξαιρέσεις:

- καθημερινή που δηλώνεται μη εργάσιμη,
- Σαββατοκύριακο ή ειδική ημέρα που δηλώνεται εργάσιμη.

### `Class`

Τμήμα σχολικού έτους. Έχει `name`, `year`, `responsibleTeacherId`, μαθητές, μαθήματα και χρήστη τάξης.

### `Teacher`

Εκπαιδευτικός με φυσικό κλειδί `am`. Συνδέεται με `User`, μαθήματα και τμήματα ευθύνης.

### `Student`

Μαθητής με `am`, όνομα, επώνυμο, πατρώνυμο, τμήμα, γονέα και σχολικό έτος.

### `Parent`

Γονέας με email και user account. Το username του user λειτουργεί ως πρακτικό κλειδί εισαγωγής από Excel.

### `Course`

Μάθημα τμήματος με `aa`, όνομα και έναν εκπαιδευτικό μέσω `CourseTeacher`.

Το ειδικό μάθημα `ΑΝΑΠΛΗΡΩΣΗ` σημειώνεται με `isSubstitution`. Σε αυτό το μάθημα ο εκπαιδευτικός δεν προκύπτει από το βασικό `CourseTeacher`, αλλά επιλέγεται πάνω στο συγκεκριμένο απουσιολόγιο ή στην ημερήσια αλλαγή προγράμματος.

### `ScheduleSlot`

Ορίζει πρόγραμμα: τμήμα, ημέρα, ώρα, μάθημα. Για διπλά μαθήματα στην ίδια ώρα υπάρχουν δύο εγγραφές με ίδιο `classId/day/hour` και διαφορετικό `courseId`.

### `AttendanceSheet`

Το πραγματικό απουσιολόγιο ανά `classId`, `date`, `hour`.

Σημαντικό constraint:

```text
unique(classId, date, hour)
```

Άρα κάθε τμήμα έχει ένα απουσιολόγιο για κάθε ημερομηνία και ώρα.

### `AttendanceSheetCourse`

Τα μαθήματα/εκπαιδευτικοί που συμμετέχουν σε ένα φύλλο απουσιολογίου. Υποστηρίζει μέχρι δύο μαθήματα ανά ώρα στο UI.

Κρατά ξεχωριστό `teacherId` και `signedAt` ανά μάθημα, άρα υποστηρίζεται:

- μερική υπογραφή,
- προσωρινή αλλαγή εκπαιδευτικού,
- αναπλήρωση από εκπαιδευτικό που δεν έχει κανονικό μάθημα στο τμήμα.

### `AttendanceSheetAbsence`

Απουσία μαθητή σε συγκεκριμένο απουσιολόγιο. Το `isHourlyExpulsion` σημειώνει ότι η απουσία προέρχεται από **Ωριαία αποβολή**.

Πρωτεύον κλειδί:

```text
sheetId + studentId
```

Σχετική migration:

```text
prisma/migrations/20260524071820_substitution_and_hourly_expulsion/migration.sql
```

Η migration προσθέτει:

- `Course.isSubstitution`
- `AttendanceSheetAbsence.isHourlyExpulsion`
- πεδία/κανόνες που επιτρέπουν αναπλήρωση και ειδική σήμανση απουσίας.

## 10. Ημερολόγιο και ημερομηνίες

Η λογική βρίσκεται στο `lib/school-calendar.ts`.

Κανόνες:

1. Η ημερομηνία πρέπει να είναι μέσα στα `startsOn` / `endsOn` του σχολικού έτους.
2. Αν υπάρχει εγγραφή `SchoolCalendarDay`, υπερισχύει.
3. Αν δεν υπάρχει εγγραφή, εργάσιμες είναι οι καθημερινές.
4. Το API του απουσιολογίου ελέγχει server-side τα παραπάνω.

Τα datepickers σε απουσιολόγιο, μαθήματα και εκτυπώσεις παίρνουν `min` και `max` από το ενεργό σχολικό έτος.

## 11. Ροή απουσιολογίου

Η κύρια σελίδα είναι `app/page.tsx`.

Αν ο χρήστης δεν έχει session, εμφανίζεται login.

Μετά το login:

- `PARENT`: redirect σε `/parent`
- `CLASS_TABLET`: ανοίγει απευθείας το τμήμα του
- `TEACHER`: ανοίγει απουσιολόγιο αφού επιλεγεί τμήμα
- `ADMIN`: βλέπει επιλογή τμήματος και πλήρες admin sidebar

Η επιλογή ημερομηνίας/ώρας υπολογίζεται από:

- την τρέχουσα ώρα Ελλάδας,
- το σχολικό ωράριο,
- το ενεργό σχολικό έτος,
- τις εξαιρέσεις ημερολογίου.

Το UI απουσιολογίου βρίσκεται στο `app/attendance-board.tsx`.

## 12. API απουσιολογίου

Endpoint: `/api/attendance`

### GET

Φορτώνει payload για:

```text
classId
date
day
hour
```

Ελέγχει:

- session,
- αλλαγή κωδικού,
- εγκυρότητα ημερομηνίας,
- δικαίωμα πρόσβασης τάξης για `CLASS_TABLET`.

Επιστρέφει:

- μαθητές,
- μαθήματα τμήματος,
- διαθέσιμες επιλογές μαθήματος,
- διαθέσιμους εκπαιδευτικούς για αναπλήρωση,
- τρέχουσες απουσίες,
- υπογραφές ανά μάθημα,
- κατάσταση αποθήκευσης.

### PUT

Αποθηκεύει πρόχειρο, υπογράφει ή ακυρώνει υπογραφή.

`action`:

- `draft`
- `sign`
- `unlock`

Κανόνες:

- Μέχρι δύο μαθήματα ανά ώρα.
- Τα μαθήματα πρέπει να ανήκουν στο τμήμα, εκτός από το ειδικό μάθημα `ΑΝΑΠΛΗΡΩΣΗ`.
- Στην αναπλήρωση απαιτείται επιλογή εκπαιδευτικού πάνω στο συγκεκριμένο `AttendanceSheetCourse`.
- Οι απουσίες μπορούν να έχουν flag `isHourlyExpulsion`.
- Το tablet τμήματος μπορεί να υπογράψει μόνο αν δοθεί σωστό password εκπαιδευτικού.
- Ο εκπαιδευτικός μπορεί να υπογράψει μόνο μάθημα στο οποίο είναι ορισμένος ή αναπλήρωση στην οποία έχει επιλεγεί ως εκπαιδευτικός.
- Ο admin χωρίς teacher record μπορεί να υπογράψει/ξεκλειδώσει όλα.
- Υπογεγραμμένο φύλλο έχει `signedAt` μόνο όταν όλα τα `AttendanceSheetCourse` έχουν `signedAt`.
- Αν υπάρχει μία μόνο υπογραφή από τα δύο μαθήματα, το φύλλο είναι σε μερική υπογραφή.

## 13. Υπογραφές και ξεκλείδωμα

Το απουσιολόγιο κλειδώνει πλήρως όταν όλα τα μαθήματα της ώρας έχουν υπογραφεί.

Για διπλό μάθημα:

- κάθε μάθημα έχει δικό του εκπαιδευτικό,
- κάθε εκπαιδευτικός υπογράφει χωριστά,
- εμφανίζεται κατάσταση μερικής υπογραφής,
- η ακύρωση υπογραφής μπορεί να γίνει από έναν εκπαιδευτικό που έχει υπογράψει.

Στο tablet τάξης η υπογραφή γίνεται χωρίς αλλαγή λογαριασμού: ο εκπαιδευτικός πληκτρολογεί μόνο τον κωδικό του.

### Αναπλήρωση

Η αναπλήρωση υλοποιείται ως ειδικό μάθημα `ΑΝΑΠΛΗΡΩΣΗ`.

Ροές:

- Στο απουσιολόγιο, αν το φύλλο δεν έχει υπογραφεί, μπορεί να επιλεγεί `ΑΝΑΠΛΗΡΩΣΗ` και συγκεκριμένος εκπαιδευτικός.
- Στο πρόγραμμα, ο admin μπορεί να ορίσει ημερήσια αλλαγή με `ΑΝΑΠΛΗΡΩΣΗ` και εκπαιδευτικό.
- Το δικαίωμα υπογραφής ακολουθεί τον εκπαιδευτικό που είναι αποθηκευμένος στο `AttendanceSheetCourse.teacherId`.

### Ωριαία αποβολή

Η ωριαία αποβολή είναι flag πάνω στην απουσία μαθητή (`AttendanceSheetAbsence.isHourlyExpulsion`). Η απουσία μετρά κανονικά, αλλά εμφανίζεται με ειδική ένδειξη στις αναφορές γονέα, στις αναφορές υπεύθυνου τμήματος, στις εκτυπώσεις και στο CSV export.

## 14. Admin διαχείριση

Η σελίδα `app/admin/page.tsx` παρέχει CRUD για:

- σχολικά έτη,
- τμήματα,
- εκπαιδευτικούς,
- γονείς,
- μαθητές,
- μαθήματα,
- πρόγραμμα,
- εισαγωγή Excel,
- μετάβαση σε επόμενο σχολικό έτος.

Οι server actions βρίσκονται στο `app/admin/actions.ts`.

Η σελίδα είναι οργανωμένη σε tabs ώστε να μη φορτώνει οπτικά όλες τις φόρμες μαζί:

- `Έτη / Excel`
- `Τμήματα`
- `Εκπαιδευτικοί`
- `Γονείς`
- `Μαθητές`
- `Μαθήματα`
- `Πρόγραμμα`

Στο tab `Έτη / Excel` υπάρχει επίσης action `deleteSchoolYearDataAction`. Διαγράφει ένα σχολικό έτος μαζί με τα συνδεδεμένα τμήματα, μαθητές, μαθήματα, πρόγραμμα, απουσιολόγια, αργίες, λογαριασμούς τμημάτων και ορφανούς μη-admin γονείς/εκπαιδευτικούς. Απαιτεί server-side επιβεβαίωση με τη λέξη `ΔΙΑΓΡΑΦΗ` και δεν διαγράφει admin λογαριασμούς.

### Μετάβαση σε επόμενο έτος

Η `promoteSchoolYearAction`:

1. αρχειοθετεί το ενεργό έτος,
2. δημιουργεί νέο ενεργό σχολικό έτος,
3. μεταφέρει τμήματα με μετάβαση τάξης:
   - Α → Β
   - Β → Γ
   - Γ δεν μεταφέρεται
4. αντιγράφει μαθητές,
5. αντιγράφει μαθήματα,
6. αντιγράφει εκπαιδευτικούς μαθημάτων,
7. αντιγράφει πρόγραμμα,
8. δημιουργεί χρήστες τμημάτων με username από το νέο τμήμα.

## 15. Excel import

Το πρότυπο παράγεται από:

```text
GET /admin/import-template
```

Φύλλα:

- `Σχολικά έτη`
- `Τμήματα`
- `Εκπαιδευτικοί`
- `Γονείς`
- `Μαθητές`
- `Μαθήματα`
- `Πρόγραμμα`

### Κλειδιά και αναφορές

| Οντότητα | Κλειδί εισαγωγής |
| --- | --- |
| Εκπαιδευτικός | `ΑΜ` |
| Γονέας | `username` |
| Μαθητής | `ΑΜ` + σχολικό έτος |
| Τμήμα | λεκτικό τμήματος + σχολικό έτος, π.χ. `Α1` |
| Μάθημα | `ΑΑ` + τμήμα |
| Πρόγραμμα | τμήμα + ημέρα + ώρα |

Στο φύλλο `Πρόγραμμα`, τα πολλά μαθήματα της ίδιας ώρας δηλώνονται στο πεδίο `ΑΑ μαθήματος` με `;`, π.χ.:

```text
M001;M002
```

### Συμπεριφορά επανεισαγωγής

Η εισαγωγή χρησιμοποιεί `upsert` όπου υπάρχει φυσικό κλειδί. Αυτό σημαίνει ότι:

- σχολικά έτη ενημερώνονται ή δημιουργούνται,
- εκπαιδευτικοί ενημερώνονται με βάση το ΑΜ,
- γονείς ενημερώνονται με βάση το user,
- τμήματα ενημερώνονται με βάση σχολικό έτος + όνομα,
- μαθήματα ενημερώνονται με βάση τμήμα + ΑΑ,
- το πρόγραμμα για ίδια ημέρα/ώρα αντικαθίσταται με τις νέες εγγραφές.

Άρα, σε σωστά συμπληρωμένο αρχείο δεν δημιουργούνται διπλοεγγραφές για τις ίδιες οντότητες.

Οι ημερομηνίες σχολικού έτους στο import περνούν από `importedDate`, ώστε να υποστηρίζονται Excel serial dates, `yyyy-mm-dd` και `dd/mm/yyyy`.

## 16. Αναφορές και εκτυπώσεις

### Reports

Η σελίδα `/reports` δείχνει:

- τμήματα ευθύνης για εκπαιδευτικούς,
- όλα τα τμήματα για admin,
- απουσίες,
- αιτήματα δικαιολόγησης,
- ενέργειες δικαιολόγησης/αφαίρεσης απουσίας.

### Print center

Η σελίδα `/print` παρέχει:

- ημερήσιο απουσιολόγιο τμήματος,
- ατομική κατάσταση μαθητή.

Οι εκπαιδευτικοί βλέπουν μόνο τμήματα στα οποία είναι υπεύθυνοι. Ο admin βλέπει όλα.

### Parent portal

Η σελίδα `/parent` δείχνει για κάθε παιδί:

- συνολικές απουσίες,
- αναλυτικές απουσίες ομαδοποιημένες ανά ημερομηνία,
- ένδειξη για `Ωριαία αποβολή`,
- πρόγραμμα τμήματος με datepicker και σεβασμό αργιών.

Η σελίδα `/parent/absences-report` παράγει εκτυπώσιμη αναφορά απουσιών ανά παιδί, με συνολικά και αναλυτικά στοιχεία.

## 17. Dashboard και ειδοποιήσεις

Το `/dashboard` συγκεντρώνει στατιστικά απουσιών, εκκρεμότητες και εικόνα τμημάτων.

Το `/notifications` περιέχει:

- κανόνες ειδοποιήσεων,
- δημιουργία ειδοποιήσεων,
- ουρά ειδοποιήσεων,
- σήμανση ως σταλμένες.

Οι κανόνες email είναι ακόμα εφαρμοστικοί κανόνες/ουρά. Η πραγματική αποστολή email μπορεί να συνδεθεί σε επόμενο βήμα με πάροχο email.

Το `/control` είναι admin-only σελίδα για επιχειρησιακό έλεγχο:

- δημιουργεί ενημερώσεις πρώτης ώρας για συγκεκριμένη ημερομηνία,
- στέλνει email αν υπάρχουν `RESEND_API_KEY` και `EMAIL_FROM`,
- κρατά τις αποτυχημένες/μη ρυθμισμένες αποστολές ως `QUEUED` ειδοποιήσεις,
- εκτελεί rules-based ανάλυση μοτίβων απουσιών ανά μαθητή, μάθημα, ώρα, ημέρα και πλήρη ημέρα.

Η ανάλυση μοτίβων είναι επίτηδες deterministic στο πρώτο στάδιο. Μπορεί να επεκταθεί με AI service που θα παίρνει τα συγκεντρωτικά ευρήματα, όχι ακατέργαστα προσωπικά δεδομένα, και θα παράγει σχολιασμό/προτεραιοποίηση για τον admin.

## 18. Εκκρεμότητες υπογραφών

Η σελίδα `/pending` υπολογίζει απουσιολόγια που θα έπρεπε να έχουν υπογραφεί αλλά εκκρεμούν.

Η λογική βρίσκεται στο `lib/pending-attendance.ts` και λαμβάνει υπόψη:

- ενεργό σχολικό έτος,
- ημερομηνίες έναρξης/λήξης,
- εργάσιμες ημέρες και αργίες,
- εβδομαδιαίο πρόγραμμα και ημερήσιες αλλαγές,
- παρελθούσες ημερομηνίες, όχι μελλοντικές.

Ο εκπαιδευτικός βλέπει τις δικές του εκκρεμότητες και ανοίγει το αντίστοιχο απουσιολόγιο για διόρθωση/υπογραφή. Ο admin μπορεί να δει όλες τις εκκρεμότητες και να ορίσει μια ώρα ως `ΚΕΝΟ`, αν π.χ. απουσίαζε ο εκπαιδευτικός.

## 19. Styling και UI

Το styling βρίσκεται στο `app/globals.css`.

Κύρια patterns:

- `app-shell`, `topbar`, `workspace`, `sidebar`, `main-grid`
- `admin-section`, `admin-form`, `admin-table`, `admin-row`
- `panel`, `metric`, `status-message`
- `primary-button`, `secondary-button`, `icon-button`

Σημαντικό: το απουσιολόγιο χρησιμοποιεί ειδικό client component με δικό του sidebar στο `attendance-board.tsx`, ενώ οι περισσότερες άλλες σελίδες χρησιμοποιούν `AppNavigation`.

## 20. Deployment

Προτεινόμενη δωρεάν δοκιμή:

- GitHub repo
- Vercel για hosting
- Neon για PostgreSQL

Βήματα:

1. Ρύθμιση Neon database.
2. Προσθήκη `DATABASE_URL` στο Vercel.
3. Προσθήκη `NEXTAUTH_SECRET`.
4. Προσθήκη `ADMIN_USERNAME` και `ADMIN_PASSWORD`.
5. Deploy από GitHub.

Το `vercel-build` εκτελεί migrations και δημιουργεί admin.

## 21. Έλεγχοι πριν από αλλαγές/PR

Πριν από push/deploy:

```bash
npm run prisma:generate
npx tsc --noEmit
npm run lint
npm run build
```

Αν έχει προστεθεί migration:

```bash
npm run db:deploy
```

Σε development, αν εμφανιστούν περίεργα σφάλματα React Client Manifest ή άστυλη σελίδα μετά από build ενώ τρέχει dev server:

```bash
rm -rf .next
npm run dev
```
